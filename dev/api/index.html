API reference

Every public name of AbstractMultiscaleTransforms. Names listed with the AbstractMultiscaleTransforms. prefix are public but not exported.

AbstractMultiscaleTransforms — Module
AbstractMultiscaleTransforms

The interface shared by multiscale transform packages (contourlets, surfacelets, shearlets, wavelets, ...): transform objects, the verbs analyze and synthesize, reusable workspaces, and subband access on array-valued coefficients. It defines no transform of its own.

A package implementing a transform depends on this one, subtypes AbstractMultiscaleTransform, adds methods to the verbs and accessors, re-exports them, and checks its types with AbstractMultiscaleTransforms.Testing.test_transform.

Transforms and verbs

AbstractMultiscaleTransforms.AbstractMultiscaleTransform — Type
AbstractMultiscaleTransform

Supertype of transform objects. A transform is an immutable value that holds every parameter of the decomposition (number of scales, directions per scale, filters, ...) and nothing that depends on the data's size or element type, so one transform serves arrays of any admissible size. Two transforms with equal parameters are == and have equal hash.

An implementation defines, for its transform type T:

RequiredPurpose
analyze!(c, t::T, x; workspace, threaded)analysis into preallocated coefficients
synthesize!(x, t::T, c; workspace, threaded)synthesis into a preallocated array
similar_coefficients(t::T, x)uninitialised coefficients for data like x
subband_layout(t::T, dims)one descriptor per subband
subband(t::T, c, i)subband i of c, a view
preserves_real(t::T)whether real data gives real coefficients
OptionalDefault
analyze(t::T, x; ...)analyze!(similar_coefficients(t, x), t, x; ...)
synthesize(t::T, c; ...)synthesize! into an array of size signal_size(t, c)
signal_size(t::T, c)needed by the default synthesize, except for SubbandVector coefficients
make_workspace(t::T, T, dims; ...) / make_workspace(t::T, x; ...)a DefaultWorkspace
nsubbands(t::T, dims)length(subband_layout(t, dims))
analyze(f, t::T, x; ...), synthesize!(f, x, t::T; ...) with supports_streaming(t::T) = truenot supported

Every implementation also follows these conventions; AbstractMultiscaleTransforms.Testing.test_transform checks most of them:

  • The transform holds every parameter, is immutable, and two transforms with equal parameters are == and have equal hash.
  • Every verb accepts the keywords workspace and threaded. A method that receives a workspace checks it with check_workspace before using it.
  • Wrong input throws before any work: a DimensionMismatch for a wrong size, an ArgumentError for another wrong argument, each with a message.
  • The transform is linear over the complex numbers: analyze(t, x + im * y) ≈ analyze(t, x) + im * analyze(t, y) for real x and y. When preserves_real is true, its filters are real, so real data gives real coefficients and complex data is transformed as its real and imaginary parts.
  • A multiscale transform puts the lowpass first: subband 1 holds the coarse content. A transform without a lowpass subband, such as a uniform filter bank, orders its subbands as its documentation states.
  • The implementing package lists the interface's exported names in its own export, so that using it is enough.

AbstractMultiscaleTransforms.analyze — Function
analyze(t, x; workspace = nothing, threaded = nothing) -> c
analyze(ws, x; threaded = nothing) -> c

Analysis (forward) transform of the array x by the transform t. The coefficients c are an array: transforms whose subbands all have the size of x stack them into one array of size (size(x)..., n); critically sampled separable transforms may pack them as blocks of one array of the size of x; others return a SubbandVector or a package-specific array. Read subbands with subband; synthesize inverts the transform.

workspace is a workspace from make_workspace matching t and x; threaded = nothing leaves threading to the transform's documented default, true/false asks for or against threads (a transform that never threads ignores it).

analyze(f, t, x; workspace = nothing, threaded = nothing) -> nothing

Streaming form (only where supports_streaming(t)): calls f(i, band) once for every subband i instead of storing the coefficients. band is valid only until f returns.

AbstractMultiscaleTransforms.synthesize — Function
synthesize(t, c; workspace = nothing, threaded = nothing) -> x
synthesize(ws, c; threaded = nothing) -> x

Synthesis transform: the array whose analysis is c, so that synthesize(t, analyze(t, x)) ≈ x. This is the adjoint of analyze only when the transform is a tight (Parseval) frame; each package documents whether its transforms are.

The result has the element type of the workspace's data, or without one, of c. So when preserves_real(t) is false, synthesize(t, c) of the coefficients of real data is complex; pass a workspace, or call synthesize! with a real array, to get real data.

Workspaces

AbstractMultiscaleTransforms.AbstractTransformWorkspace — Type
AbstractTransformWorkspace

Supertype of workspaces: everything a transform precomputes for one data size, element type and array type (filter responses, FFT plans, scratch buffers), so that repeated calls allocate little or nothing. Build one with make_workspace.

A workspace answers transform, eltype (the data element type) and size (the data size). It holds scratch buffers, so it serves one call at a time; give each task its own. A call whose transform, size or element type does not match the workspace throws (see check_workspace).

A workspace can stand in for its transform: analyze(ws, x) is analyze(transform(ws), x; workspace = ws), and likewise for the other verbs.

A transform that has plans or buffers to reuse defines its own subtype, with methods for transform, eltype and size, and make_workspace methods for make_workspace(t, T, dims) and, if the workspace depends on the array type (a GPU array, say), for make_workspace(t, x). Both accept the shared keywords listed there. A transform without one gets a DefaultWorkspace.

source
AbstractMultiscaleTransforms.make_workspace — Function
make_workspace(t, T::Type{<:Number}, dims; kwargs...) -> AbstractTransformWorkspace
make_workspace(t, x::AbstractArray; kwargs...) -> AbstractTransformWorkspace

Precompute what transform t needs for data of element type T and size dims. The second form takes element type, size and array type (so the device) from x.

Every transform accepts these keywords on both forms, so that code can build a workspace without knowing the transform family. A transform with no use for one accepts and ignores it, and says so in its documentation; the defaults are the transform's own (its fastest choice).

  • flags: the FFTW planner flags of the host FFT plans (an integer, such as FFTW.MEASURE or FFTW.ESTIMATE).
  • tasks: the most tasks a call with the workspace runs on the host, and with them the per-task buffers; nothing means one per Julia thread, 1 a serial workspace.
  • tune: measure the fastest batching of a device workspace at construction (a Bool).
  • prewarm: run the transform once at construction, so that the first call is compiled and allocates nothing (a Bool).

A transform may accept further keywords of its own. An unknown keyword throws a MethodError.

Without a method for t, both return a DefaultWorkspace, which holds nothing but (t, T, dims) and ignores the keywords above.

AbstractMultiscaleTransforms.DefaultWorkspace — Type
DefaultWorkspace(t, T, dims)

The workspace of a transform that precomputes nothing: it records the transform, data element type T and data size dims, so that the workspace forms of the verbs and check_workspace work for every transform. Returned by the fallback make_workspace.

AbstractMultiscaleTransforms.check_workspace — Function
check_workspace(ws, t, T, dims) -> ws

Throw unless workspace ws was built for transform t, data element type T and data size dims: an ArgumentError for another transform or element type, a DimensionMismatch for another size. Implementations call it on a workspace keyword before using it.

AbstractMultiscaleTransforms.SubbandVector — Type
SubbandVector(data::AbstractVector, layout::SubbandLayout)

Coefficients made of subbands of different sizes, stored one after another in the single vector data (a host Vector or a device vector) and presented as an AbstractVector of all coefficients. subband(c, i) is a reshaped view of subband i.

Broadcasting, similar, copyto!, fill!, ==, isapprox, mapreduce (sum, maximum, ...) and LinearAlgebra.dot/norm/axpy!/axpby!/ rmul!/lmul! act on data directly, so they need no scalar indexing on a device and keep the layout. Operands of one operation must share a layout. Adapt.adapt moves the storage (a method defined once Adapt is loaded, as every GPU array package does).

julia> using AbstractMultiscaleTransforms

julia> layout = SubbandLayout([(2, 2), (4, 4)], (4, 4));

julia> c = SubbandVector(collect(1.0:20.0), layout);

julia> subband(c, 1)
2×2 reshape(view(::Vector{Float64}, 1:4), 2, 2) with eltype Float64:
 1.0  3.0
 2.0  4.0

julia> d = 2 .* c .+ 1;

julia> d isa SubbandVector && subband(d, 1)[1] == 3.0
true

AbstractMultiscaleTransforms.SubbandLayout — Type
SubbandLayout(sizes, signal_size)

Where each subband of a SubbandVector lies in its flat storage: subband i has size sizes[i] and occupies the next prod(sizes[i]) entries after subband i - 1. signal_size is the size of the data the coefficients describe. Layouts are compared by value.

Element types

AbstractMultiscaleTransforms.preserves_real — Function
preserves_real(t) -> Bool

Whether t maps real data to real coefficients and real coefficients back to real data, as a transform with real filters does. A transform with complex filters (curvelets as computed by CurveLab, a dual-tree complex wavelet transform, a complex steerable pyramid, a short-time Fourier transform, a Morlet wavelet transform) returns false; its similar_coefficients returns a complex array for real data. Both kinds are linear over the complex numbers.

Every transform type defines a method: neither answer is a safe default, and the fallback throws an ArgumentError.

source
AbstractMultiscaleTransforms.Testing.test_transform — Function
test_transform(t, x; rtol, wrong_size = nothing, exact_real_linear = false)

Needs the Test standard library loaded (using Test), which defines the method.

Run the interface's conformance tests for transform t on data x, inside a @testset:

  • analyze returns an array, whose nsubbands(t, size(x)) subbands cover all of its entries; synthesize reconstructs x (to rtol);
  • analyze!/synthesize! into preallocated arrays, the workspace (make_workspace) and workspace-only forms, and threaded = true/false give the same results;
  • both make_workspace forms accept the shared keywords flags, tasks, tune and prewarm, the workspace built with them gives the same results, and an unknown keyword throws a MethodError;
  • the transform equals its copy, with an equal hash;
  • broadcasting, similar, copyto!, norm and dot work on the coefficients;
  • the streaming forms, if supports_streaming(t), give the same subbands and reconstruction;
  • a workspace for another size (wrong_size, when given) is rejected;
  • when preserves_real(t), the coefficients of real data are real (for complex x, checked on real(x));
  • for complex x, the transform is linear over the complex numbers: analyze(t, x) ≈ analyze(t, real(x)) + im * analyze(t, imag(x)), exactly (==) when exact_real_linear (meaningful when preserves_real(t), where the right side is formed with complex.); each side runs through a workspace built once, so that FFT planning between calls cannot change the rounding.
